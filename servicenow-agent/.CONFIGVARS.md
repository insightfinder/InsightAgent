### Config Variables

#### Credentials -- `.env`, never `config.ini`
Credentials are not config keys at all -- they're read from the environment. Copy `example.env` to `.env`; the agent loads it from its own directory automatically at startup (real env vars, if set, always take priority over the file). See the README's "Credentials (.env)" section.
* **`SERVICENOW_OAUTH_CLIENT_ID`** / **`SERVICENOW_OAUTH_CLIENT_SECRET`** / **`SERVICENOW_OAUTH_USERNAME`** / **`SERVICENOW_OAUTH_PASSWORD`**: Required when `auth_type = oauth2`.
* **`SERVICENOW_USERNAME`** / **`SERVICENOW_PASSWORD`**: Required when `auth_type = basic`.

#### `[servicenow]` -- connection (not overridable per query)
* **`base_url`**: Instance base URL, no trailing path. e.g. `https://acme.service-now.com`.
* **`auth_type`**: `oauth2` (default) or `basic`. Determines which `.env` variables are required. OAuth2 always uses the password grant against `/oauth_token.do` -- not configurable, since it's the only combination that works against a real instance without extra ServiceNow-side setup (`client_credentials` needs an OAuth Entity Profile most instances don't have).
* `verify_certs`: `true` (default) or `false`.
* `ca_certs`: Path to a CA bundle.
* `agent_http_proxy` / `agent_https_proxy`: Proxy for requests to ServiceNow.
* `query_chunk_size`: Records per page (`sysparm_limit`). Default `1000`.
* `query_time_offset_seconds`: Backs the window's upper bound off by this much, absorbing clock skew between this host and the instance. Default `30`. Every run's query window is exactly the last `[insightfinder] sampling_interval` seconds, offset by this -- no state is kept between runs, so `run_interval` and `sampling_interval` should match (see README "How ticket data becomes a log entry").
* `his_time_range`: Replay a fixed range instead of the live `sampling_interval`-sized window. Format `YYYY-MM-DD HH:MM:SS,YYYY-MM-DD HH:MM:SS`.

#### `[servicenow]` defaults, overridable per `[query:NAME]`
Setting any of these in `[servicenow]` gives every query that default; setting the same key inside a `[query:NAME]` section overrides it for that query only.
* **`table`** (query-only, required): The ServiceNow table, e.g. `incident`, `em_alert`.
* `sysparm_query`: An encoded ServiceNow query, written literally -- `%` and `^` need no escaping. The agent appends its own time filter and a total-order `ORDERBY`; do not add your own timestamp filter or `ORDERBY` clause.
* `data_fields`: Comma-delimited ServiceNow fields. Sent as `sysparm_fields` on the wire *and* used to select the output `data` -- narrowing it shrinks the response too. Dot-walk reference fields (`cmdb_ci.name`, `assignment_group.name`) to fetch a related record's column in the same request. **Leave blank to fetch and send every field on the record.**
* `timestamp_field`: Default `sys_created_on`. Use `sys_updated_on` instead if a ticket's later edits (state changes, resolution, etc.) should also re-surface it in the query window.
* `timestamp_format`: [arrow](https://arrow.readthedocs.io/en/latest/#supported-tokens) format. Default `YYYY-MM-DD HH:mm:ss` (ServiceNow's internal format). The agent always reads a timestamp field's `.value` (UTC internal representation), never `.display_value` (rendered in the integration user's locale).
* `timezone`: Timezone the raw timestamp value is in, as per pytz. Default `UTC`.
* `target_timestamp_timezone`: Timezone the timestamp is stored as in InsightFinder. Default `UTC`.
* `instance_field`: Comma-separated priority list of fields; the first non-empty value becomes the ticket's `tag` (InsightFinder instance name). Fields from a reference lookup keep their dotted name as a literal key, e.g. `cmdb_ci.name`.
* `instance_field_regex`: Extract the instance via regex. Syntax: `<field1>::<regex1>,<field2>::<regex2>`.
* `instance_whitelist`: Regex; instances not matching are dropped.
* `default_instance_name`: Used when no `instance_field` value is found.
* `project_name` (query-only): Sends this query's tickets to a different InsightFinder project (auto-created) instead of `[insightfinder] project_name`.

Not supported: `component_field`. LOG-mode entries are `{eventId, tag, data}` -- there is no `componentName`, so this key would silently do nothing. Put ownership/team context inside `data` instead.

#### `[insightfinder]`
* **`user_name`**: User name in InsightFinder.
* **`license_key`**: License key from your Account Profile in the InsightFinder UI.
* `token`: Authentication token, alternative to `license_key`.
* **`project_name`**: Default project for tickets that don't set their own `project_name`. Auto-created if it doesn't exist.
* `system_name`: System owning the project, used on auto-create. Falls back to `project_name`.
* **`project_type`**: Must be `log` or `logreplay` -- this agent only supports LOG.
* `containerize`: `YES` for container projects. Default `no`.
* `enable_holistic_model`: Default `false`.
* **`sampling_interval`**: How frequently data is collected; also the exact size of every run's ServiceNow query window (in seconds back from now). Must match `run_interval` -- see "How ticket data becomes a log entry" in the README.
* `frequency_sampling_interval`: Hot/cold event detection frequency in minutes, used on project auto-create. Default `10`.
* **`run_interval`**: How frequently the agent runs. Should match the cron schedule.
* `worker_timeout`: Worker process timeout, minutes. Default: same as `run_interval`.
* `log_compression_interval`: Log de-dup window, minutes. Default `1`.
* `enable_log_rotation` / `log_backup_count`: Daily log rotation. Default `false` / `14`.
* `chunk_size_kb`: Size of chunks sent to InsightFinder, in KB. Default `2048`.
* `if_url`: InsightFinder URL. Default `https://app.insightfinder.com`.
* `if_http_proxy` / `if_https_proxy`: Proxy for the InsightFinder connection.
